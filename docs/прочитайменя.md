# Чё это вообще такое

Короче, это файловый менеджер. Ну, то же самое, что твой "Проводник" в винде или "Файлы"
в убунте — только для Linux, пишется с нуля, и самая сочная фишка: он **сам раскидывает
твой бардак по папкам с помощью локальной нейронки**. Без интернета, без отправки твоих
файлов куда-то в облако — вся магия происходит на твоём же компе через Ollama (это такая
штука, которая гоняет нейронки типа Llama прямо у тебя на железе).

Представь: у тебя в "Загрузках" три года хаоса — скриншоты, счета, курсовые, мемы,
установщики. Ты такой: `fm sort ~/Downloads --prompt "разложи по смыслу" --apply` — и
нейронка реально читает, что внутри файлов (не просто смотрит на расширение, а СОДЕРЖИМОЕ
открывает), и раскладывает по папкам сама. Фотки — по годам и событиям, счета — в
"Финансы", код — отдельно от бинарников. Как скажешь, так и разложит.

## Почему "конструктор"

Внутри это не один большой кусок кода, а куча маленьких деталек, как Лего. Каждая делает
свою одну вещь и не лезет в чужие дела:

- одна деталька **читает файлы с диска** (быстро, вообще без интернета и нейронок)
- другая **хранит базу** — что где лежит, какие теги, какая категория
- третья **думает** — это и есть нейронка, она сидит отдельным процессом
- четвёртая **реально двигает файлы** по плану, который придумала нейронка
- пятая **следит**, не появилось ли что-то новое в папке, пока ты не смотришь
- и сверху — командная строка, которой ты всем этим рулишь

Фишка в том, что если одну детальку выкинуть и заменить другой — остальные даже не
заметят. Сдохла нейронка, Ollama не запущена, инета нет — тебе всё равно норм: можно
листать файлы, искать, сортировать по типу/дате (без ИИ, по-тупому но надёжно), всё
работает. Просто "умная" сортировка по смыслу подождёт, пока нейронку не поднимешь.

## А чё, реально без интернета?

Ага. Все нейронки крутятся локально через Ollama — она качает модели один раз (несколько
гигов, да, зависит от модели) и дальше всё работает офлайн. Никто твои пароли, фотки и
личные файлы никуда не отправляет — всё варится у тебя на компе.

## Почему так быстро листает папки

Обычный `ls` (и большинство файлменеджеров) под капотом дергает библиотечные функции,
которые делают кучу лишней работы — например, на каждый файл спрашивают "а чей это файл,
как зовут владельца?" и лезут за этим именем куда-то в систему, это не бесплатно.
Я написал обход папок напрямую через системные вызовы ядра Linux, без этой мишуры — и
на тесте в 100 000 файлов моя штука отработала **в 2.4 раза быстрее** голого `ls -la`.
Не потому что я гений, а потому что просто не делаю лишнего.

## Как это запустить, если ты не программист

Если тебе прислали этот проект и сказали "запусти" — вот по-братски, шаги:

1. **Поставь Ollama** — это прога, которая гоняет нейронку локально.
   Скачать: https://ollama.com (есть под Linux/Mac/Windows).

2. **Скачай сами нейронки** (это разовая штука, займёт время — модели весят гигабайты):
   ```
   ollama pull llama3
   ollama pull llava
   ollama pull nomic-embed-text
   ```

3. **Собери сам файловый менеджер** (нужен установленный Rust и Python, это в основном
   для разработчиков, но команды простые):
   ```
   cargo build --release
   cd ai-engine && pip install -e .
   ```

4. **Запусти "мозги"** (AI-движок, он работает в фоне):
   ```
   python -m aiengine &
   ```

5. **Пользуйся**:
   ```
   fm index ~/Downloads        — говоришь: "посмотри, что у меня тут лежит"
   fm analyze ~/Downloads      — говоришь: "а теперь разберись, что это за файлы"
   fm sort ~/Downloads --prompt "разложи по смыслу"     — она показывает ПЛАН, ничего не трогая
   fm sort ~/Downloads --prompt "разложи по смыслу" --apply   — а теперь реально разложи
   fm undo                     — передумал? откатили всё обратно, как было
   ```

Без Ollama тоже можно потыкать — есть "тестовый" режим мозгов (`--mock`), который прикидывается
нейронкой, но на деле просто смотрит на ключевые слова. Для реальной сортировки не катит,
но код погонять — самое то.

## А если нейронка ошибётся и всё сломает?

Не сломает — вот почему:

- Перед реальным перемещением файлов тебе **всегда** сначала показывают план ("вот это
  переедет сюда, это — туда"), и ничего не происходит, пока ты не добавишь `--apply`.
- Даже после `--apply` — есть команда `fm undo`, которая **откатывает всё взад**. Каждое
  перемещение файла записывается в журнал ровно в момент, когда оно происходит — так что
  даже если прога внезапно крашнется посреди сортировки тыщи файлов, откат всё равно
  сработает на то, что успело переехать.
- Файлы **никогда не затираются** — если нейронка перепутала и хочет переместить файл
  туда, где уже лежит файл с таким же именем, он не заменит его молча, а переименует
  (`файл (1).jpg`) или вообще пропустит, смотря что ты настроил.

## Если коротко про "зачем всё это"

Обычные файлменеджеры сортируют файлы по тупым правилам: "все .jpg сюда, все .pdf туда".
Этот — реально **понимает, что внутри файла написано или нарисовано**, и раскладывает по
смыслу, как будто ты сам сидел и разбирал — только быстрее и без твоего участия. А если
нейронка тебе вообще не нужна прямо сейчас — всё остальное (быстрый просмотр папок,
поиск, сортировка по типу/дате) работает само по себе, без всякого ИИ, просто потому что
так удобнее для реального использования, а не "ИИ ради ИИ".
